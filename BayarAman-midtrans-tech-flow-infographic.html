BayarAman + Midtrans Payment + Manual Payout

🎯 MVP: Invoice Midtrans, Pencairan Manual
Untuk MVP, BayarAman create invoice/payment session di Midtrans. Buyer bayar via Midtrans, status masuk lewat webhook/status API, lalu pencairan ke seller tetap manual dulu.
1 FLOW PAYMENT MIDTRANS DI MVP
1🧾

Transaction Created

Seller/buyer create transaction, amount, fee, seller bank.

2⚙️

Create Snap

Backend kirim order_id, gross_amount, customer.

POST /snap/v1/transactions
3🎟️

Token / Redirect

Midtrans balikin token dan redirect_url.

4💳

Buyer Bayar

Buyer bayar via Snap page / payment invoice.

5🔔

Webhook

Midtrans kirim notification ke backend.

POST /api/webhooks/midtrans
6💬

WA Group

Operator buat group dan announce payment masuk.

7🔐

OTP Confirm

Buyer confirm selesai lewat link + OTP.

8🏁

Manual Payout

Operator transfer seller dan record reference.

⭐ Payment valid setelah webhook/status Midtrans tervalidasi: signature, order_id, dan gross_amount harus cocok.

5 STATUS MIDTRANS KE STATUS BAYARAMAN
pendingBuyer belum selesai bayar. BayarAman: WAITING_PAYMENT.
settlementPembayaran sukses. BayarAman: PAYMENT_CONFIRMED.
captureKartu sukses/captured. BayarAman: PAYMENT_CONFIRMED.
denyPembayaran ditolak. BayarAman: PAYMENT_FAILED.
expireWaktu bayar habis. BayarAman: EXPIRED.
cancelOrder dibatalkan. BayarAman: CANCELLED.

📚 Riset Midtrans yang Dicatat

Feature yang relevan: Snap API untuk create payment, token/redirect_url untuk checkout, HTTP(S) Notification/Webhook untuk status, Transaction Status API untuk reconciliation, Refund API untuk kasus yang didukung.

Keputusan: Midtrans dipakai sejak MVP untuk payment/invoice. Yang manual dulu adalah pencairan/payout seller dan operasional WA.

⭐ Ringkasnya: Midtrans = invoice/payment collection. BayarAman = trust workflow, OTP confirmation, outcome, dan manual payout seller.
